## 可重算证据

`reports/readiness_v3/source_snapshot.json`保存上游manifest元数据、360个本地图像ID及上游manifest/预测缓存身份；`ledger.json`逐图记录来源组、历史split、排除理由和保留状态；`manifest.json`固定59图标签、图像哈希、预算8图、四种方法及种子911301；`freeze.json`绑定代码和所有输入，改变身份必须另建版本。

图像逐一按原始文件SHA256核对，标签使用上游定义的canonical JSON digest核对。首次实现混淆原始JSON文件SHA与内容digest，提前拒绝了第一张图；已依据上游data.py/common.py核实并修复，记录在failures/initial_hash_contract.json。没有修改数据以通过检查。

完整原图与权重不额外公开，继续遵循原仓库BDD100K研究许可。公开的清单/标签继承同一许可。已有40图人类批量反馈与v2冻结证据保持原样。

## 可执行门禁

复用原有human_v1.core的逐图提交、独立复核、第三人裁决与评估逻辑，新增来源隔离和冻结身份包装，避免建立第二套不一致裁决标准。

- 缺少A/B逐图记录时拒绝真实错误评分，不能将旧批量反馈或AI观察代入。
- A/B须为不同复核人；阳性、分歧、未解决情况须C裁决；未完成图不删除、不缩分母。
- 全部裁决就绪后才允许读取冻结预测缓存并产生排名，方法、阈值、预算和随机种子事先锁定。
- 全阴性时precision相对提交裁决为0，recall为null；不能解释成证明无错误。
- 原始提交的自我声明只是证据约束，不是身份认证。程序无法从字符串验证两个人实际独立，也不能自动鉴别伪造签名。

本轮59图真实错误指标为null，而不是0。未声称这59图含有多少真实错误或足够统计效能。未来如果全阴性或真实错误太少，仍无法检验排序增量；不得反复筛选测试集直到出现有利结果。

## 运行

在仓库根目录执行：

```bash
uv run python scripts/readiness_v3.py verify
uv run pytest tests/test_readiness_v3.py -q
```

后续**确实有新的原始提交时**，入口为：

```bash
uv run python scripts/readiness_v3.py score \
  --upstream /path/to/driving-data-engine \
  --a /path/to/raw-A.json --b /path/to/raw-B.json \
  --c /path/to/raw-C.json --output /path/to/new-real-result.json
```

C只在有需裁决情况时必需；路径只是CLI用法，不是已存在的人类证据。输入格式沿用human_v1.core.validate_submission，protocol须为本轮manifest的canonical digest，case_id须对应本轮59图。结果保留原始提交内容digest和完整裁决。现在不要求用户或同学重复复核，不自动发送邀请，不生成假提交。

首次保留池prepare已实际运行；再次运行应保持内容相同，否则拒绝。CI只回放已提交快照与门禁测试；本机prepare额外核对真实源图和标签，不把这两种验证混为一谈。

## 严格面试官结论

新增：核实59个可隔离来源，排除历史训练/开发/评测复用，修复文件哈希与语义哈希混淆，并让不完整人类证据无法直接进入评分。

未新增：真实标签错误准确率、guard外部有效性、模型召回改善、训练收益。上一轮70.83%仍只是开发集人工合成污染表现，本轮不提升其证据等级。

唯一尚缺：新来源图的真实逐图独立裁决，尤其真实漏标/错框和本车区域误报的区分。59图保留池提供候选来源，但不保证包含这些错误；若缺少目标类型，需另行定义并冻结新的数据收集设计，不能把它混入已经评估的同一分母。
